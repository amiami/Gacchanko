# がっちゃんこ -シーンを組み合わせて持ち物リストを作る-

## なぜ作ったか

旅行に行く際、準備するものを過去のチェックリストをそのまま使ってコピーして使っていました。

でも、季節や行き先、状況に応じて使うものが違うし、コピーすると前のチェックも残って、準備したかどうか混乱することもあります。

そんなとき、季節で必要なものが違うけど、位置ゲーで旅行するなら基本的にいるものは同じと、状況に合わせて必要なシーンを組み合わせると、次の旅行で準備するセットが出来上がる。

０から考えてチェックリストを作りたくないけど、コピーじゃない、準備する楽しさみたいなものは残しておきたいと思いこのアプリを作成しました。

## 解決すること

- ０から持ち物リストを作らなくても良くなる。
- 前回持って行ったものと今回持っていくものが混同しなくなる。

## 類似アプリ

- Notion

汎用アプリ、持ち物リストのテンプレートは作れるが、テンプレートは「丸ごとコピー」しかできない。
「位置ゲー遠征 + 夏」を掛け合わせて重複を除いた1枚を作る、という合成は手作業になる。

このアプリの価値は「リストを持つこと」ではなく「シーンを合成すると持ちものリストが完成すること」にあります。

## MVPで実装する機能

- ユーザー登録
- ログイン機能
    - ゲストログイン機能
- 持ち物チェックリスト機能
    - 準備できていないものが上側に寄せて表示される
    - イベント3日前になると強調表示
- シーン作成機能
- シーン合成機能
    - 合成時にいらない持ち物を削って持ち物リストを登録する
    - イベント予定日の登録

## 本リリース時に実装する機能

- シーン編集機能

## アプリ発展のための機能

- 持ち物チェックリストからシーンを作る機能
- イベントリマインド機能
    - LINEかメールで任意の時間に準備が終わっていない時に通知する

## 技術スタック

| 技術名 | 選定理由 |
| --- | --- |
| Rails8 | 学習でやってきたことと、CRUD処理などを効率的に開発できるため |
| Render | 主にバックエンドのサービスで、無料アカウントがあるため |
| Neon | Render内の無料DBは一定期間で消えてしまい、シーンやリストを残しておきたいため |
| Docker | ローカルを汚さず、開発環境を用意でき、本番環境への移行も容易なため |
| TailwindCSS | 拡張性が高く、デザイン方面への検討時間を減らすため |
| PostgreSQL | Railsとの相性が良く、安定したデータ管理が行えるリレーショナルデータベースであるため |

## 設計上の判断

### 保存済みリストはスナップショット

シーンと保存済みリストを「参照」で繋ぐと、シーンを編集したときに
過去のリストまで書き換わってしまう。保存済みリストは「その時の記録」なので、
保存時点でアイテムを実体としてコピーする方式を採用した。

このため、シーンを削除しても過去のリストは一切影響を受けない。

## スコープ外としたこと

MVPとして「シーンを合成して持ち物リストを作る」という核の体験を優先し、以下は見送りました。

- **テストの拡充**: CIはRails標準構成のまま通しています
- **TailwindCSS**: ビルドを伴うgem版ではなくCDN版。本番化するならビルド導入が必要
- **importmap / Stimulus**: JSはERBに直書き。アセットビルドのリスクを避けたため
